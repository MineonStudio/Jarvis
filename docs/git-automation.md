# 自动提交、合并与清理

仓库开启 Auto-merge，保留 main 的 PR、quality、同步主干和讨论解决要求。配置自动化本身不要求先验收一次应用；应用的人工体验验收是每次业务改动的独立环节。

明确授权提交并合并后，可以由代理连续完成提交、推送、PR、等待 CI、合并和清理，无需逐步确认。执行自动提交入口本身代表本次分支可以在检查满足后合并，不会给仓库其他 PR 自动开启合并。

## 使用

依赖 Python 3、Git、已登录且对当前仓库有写权限的 GitHub CLI，不上传本机令牌或新增云端密钥。

在从最新 origin/main 创建的 codex/ 功能分支上完成修改、适用测试和开发版验证，检查差异并提交。将 PR 描述写入仓库外的 UTF-8 文件，然后执行：

```bash
python3 script/submit_pr.py --title "fix: 修复问题" --body-file /tmp/jarvis-pr-body.md
```

入口会推送当前分支，创建或复用本次 PR，将本次草稿 PR 标记就绪，匹配推送提交启用 Squash Auto-merge，然后等待检查和合并。main 前进导致 PR 落后时会请求 GitHub 更新分支，更新会重新触发 CI；冲突或检查失败则退出并保留分支，由代理继续修复后重试。

GitHub 在必需条件满足后自动合并，并自动删除远程功能分支，即使本机脚本退出也会继续等待合并条件。脚本持续运行时，会在确认 PR 已合并后同步本地 main、清理远程跟踪记录，并删除本次本地功能分支。

可选参数：

- `--remote-only`：等远程合并完成，但不切换或删除本地分支。适用于隔离工作区或本地 main 尚有独有提交。
- `--no-wait`：启用自动合并后返回，之后需另行检查结果和清理本地。
- `--timeout 3600`、`--interval 20`：等待上限与轮询间隔，超时不会删除分支。

## 数据保护与边界

- 不自动暂存或提交未知改动；工作区必须干净。提交由代理检查本次文件后完成。
- 不向 main 直接推送、不使用管理员绕过、不强推。
- 只对当前分支对应且提交匹配的 PR 启用自动合并。
- 本地清理要求 PR 确实已合并、本地分支和提交未改变、工作区干净、推送提交包含于 PR 的实际头提交。
- 本地 main 若有独有提交则停止同步，不执行 reset，不覆盖提交；main 在其他 worktree 使用时 Git 也会阻止切换。
- GitHub 无法直接清理本机分支，本机清理由脚本或代理完成。自动化不会发布版本，也不会自动开启现有其他 PR 的合并。
- CI 失败不等于自动修复成功：本机代理可读取日志继续处理；无人值守的 AI 修复属于额外配置，不包含在本入口中。

CI 只在 PR、main 推送及版本标签推送时运行完整 quality，避免普通功能分支同时触发 push 与 PR 的重复检查。新增脚本的回归测试也纳入 quality。
