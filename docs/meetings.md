# 会议记录

会议模块使用原生 SwiftUI 工作区和本地 Rust 引擎。语音处理技术来自 Tingo（MIT），来源和版本见 [UPSTREAM.md](../Engine/Meeting/UPSTREAM.md)。

## 开始使用

1. 在「设置 → 会议识别模型」中，下载 Paraformer-large 整套资源，约 330 MB。中断后可继续下载。安装成功前会实际加载模型验证。
2. 在原有 AI 配置中设置纪要服务。语音转写不依赖 AI 接口；未配置时也可录音、转写和回听。
3. 默认同时录制系统声音与麦克风，工具栏只提供开始／结束录音操作。F4 开始／结束，录音中详情区保留暂停操作，不再重复展示结束录音按钮；结束入口保留在工具栏、状态栏与快捷键。
4. 实时文字按约 10–30 秒一段陆续出现。结束后统一计算说话人，生成完整逐字稿。点击文字末尾的时间戳回听，再次点击同一入口停止。日期下方显示带声纹颜色的姓名标签，点击姓名试听该说话人最早的有效发言，再次点击暂停，试听到这段发言末尾自动暂停；共用详情播放器，切换说话人或手动定位会取消上一次试听。点击「改名」修改姓名或合并分组。
5. 可导入录音与录屏；纪要／逐字稿使用同文件传输一致的胶囊切换栏，默认显示纪要；待办在独立面板展示。播放栏位于说话人下方，提供播放、暂停和波形定位，并随详情内容一起滚动。每条要点与待办只展示一个主引用跳转，待办入口紧跟任务标题；期限按会议日期换算为具体日期，不附加换算说明。复制纪要提供 RTF、HTML 富文本及纯文本回退，保留标题层级与段落格式，不包含逐字稿；详情菜单与会议列表右键菜单行为一致。支持 Markdown、PDF 本地导出。

## 处理流程

- ScreenCaptureKit 在共享时间线上采集系统声音与麦克风；线下仅麦克风使用 AVAudioEngine。
- Swift 在后台音频队列写入 16 kHz 单声道 PCM WAV，持续刷新文件头；Rust 读取增长中的文件。
- 按停顿切段，经 Silero VAD、Paraformer-large int8、CT-Transformer 标点和 CAM++ 声纹处理。停止后对整场声纹统一做谱聚类，生成全场一致的说话人编号。
- 外放回声使用 Tingo 的 duck mixing：系统声音活跃时压低麦克风。双方同时讲话可能损失本地发言；耳机效果更好。这里没有真正的 AEC。
- 纪要继续调用 Jarvis 原有 AI 配置、凭据管理和流式客户端。按议题整理讨论、决议、风险和待办；长会议分段提炼再合并，保留已完成的检查点。文字引用由本机的片段编号和原文关键词校验定位。
- 设置中的术语与人名在纪要生成时纠正同音错字；Paraformer 本身不注入热词，原始逐字稿保持原样。
- 录音由用户手动结束；无人发言或会议软件退出不会自动停止。采集发生异常时停止并保留已录内容。

## 存储与恢复

默认目录为 `~/Library/Application Support/Jarvis/Meetings/`，开发版使用 `Jarvis-Dev/Meetings/`，相互隔离。

- `Models/Paraformer-large/`：识别资源，由 Jarvis 下载、验证和移除。
- `Records/`：每场会议的元信息与结构化逐字稿、纪要和历史版本。列表只读轻量元信息，搜索在后台读取详情。
- `Recordings/`：压缩后的 m4a；录音期间在每场会议的 `.capture` 子目录保留双轨 WAV。完整转写成功落盘后才清除临时 WAV。
- 删除会议会整体移到系统废纸篓。应用异常退出时，原始 WAV 仍保留，可以手动重新处理。
- 老版会议文件不自动覆盖，仍可浏览并用新引擎重新处理。旧版 Apple 语音资源和 FluidAudio 缓存不再用于新会议。

没有群推送、Obsidian 同步或独立的 AI 配置。音频不交给云端模型；生成纪要时仅把文字发往用户在既有设置中配置的服务。

## 构建和验证

安装 rustup 和 Rust 1.95.0。`build_app.sh` 自动调用 `script/build_meeting_engine.sh`，将静态链接的 sherpa-onnx 引擎打包到 `Contents/Helpers/`，先签名引擎再签名应用。用户机器不需要 Python、Rust 或 ffmpeg。

```bash
./script/build_and_run.sh --verify
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --scratch-path /Users/Shared/Jarvis/SwiftPM --filter Meeting
CARGO_TARGET_DIR=/Users/Shared/Jarvis/MeetingEngine cargo test --release --manifest-path Engine/Meeting/Cargo.toml
```

## AI 会议名称

纪要成功保存后，用现有大模型配置后台生成简短会议名称，输入仅为最终纪要的概要、讨论要点及待办摘录，不重复发送逐字稿。新录音的默认名称、导入音频的初始文件名以及先前的 AI 名称均可自动更新。标题请求有独立的输出上限与超时，失败保留原名及成功纪要，不阻塞后续会议处理。

用户实际改名后持久化标记，重新生成纪要时保留该名称；未修改的输入框失焦不视为手动改名。旧版本的自定义名称按手动名称保留。用户清空名称后回到默认名称，后续纪要生成可再次自动命名。删除、手动改名或开始新的纪要生成会取消旧标题请求；应用 AI 结果前再次检查会议是否存在、名称来源及对应纪要是否仍一致，避免过期结果覆盖新内容。
